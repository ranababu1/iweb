# Site AI Control 0.5.1

A tightly scoped WordPress AI control layer built on the WordPress Abilities API and MCP Adapter.

## What this plugin does

It exposes controlled WordPress capabilities for SEO, content auditing, content creation, publishing, post date updates, find-and-replace editing, heuristic AI-slop detection, Site Health, Search Console, PageSpeed, and GA4.

It does not contain an LLM integration. MCP is the integration contract.

## Supported architecture

```text
Claude / ChatGPT / Gemini / Qwen / Ollama / IDEs / custom MCP agents
                              |
                              v
                         MCP client
                              |
                              v
                    WordPress MCP Adapter
                              |
                              v
                     Site AI Control
```

## Ollama

The project includes a companion reference client in `site-ai-ollama-agent-0.1.0`.

It supports:

- local Ollama models
- Ollama Cloud models through the local Ollama application
- read-only Site AI operations without approval prompts
- write/publish operations with an explicit `APPROVE` prompt
- only the `site-ai/*` namespace

Ollama documents that cloud models can be run from the local Ollama application while continuing to use local tools.

## Security

This plugin intentionally does not expose:

- arbitrary SQL
- shell execution
- filesystem operations
- arbitrary PHP execution
- plugin/theme management
- arbitrary options
- arbitrary post meta
- generic bulk write operations (the 0.4.0 bulk abilities are field-scoped: dates and content substitution only, with per-post permission checks)

Use a dedicated WordPress user for AI agents.

## Dependencies

- WordPress 6.9+
- PHP 7.4+
- WordPress MCP Adapter
- Yoast SEO for SEO features
- Site Kit by Google for Google data features
- `Enable Abilities for MCP` only when using its OAuth layer

## Important

The MCP server is universal. The WordPress plugin should not contain vendor-specific code for Claude, OpenAI, Google, Qwen, Ollama, or any other model provider.


### Category intelligence

`site-ai/get-categories` exposes WordPress post categories with their post counts and can return only empty categories.


## Bulk content operations

Site AI Control 0.4.0 adds three abilities designed for low-token bulk work:

- `site-ai/update-post-dates` sets or shifts publish dates for explicit post IDs or a taxonomy selection. Backdating the newest published post by a week is a single call: `mode=shift`, `shift=-7 days`, `limit=1`. `mode=set` applies one date (`Y-m-d` keeps each post's time of day). `dry_run=true` previews. Post status and content are never changed.
- `site-ai/find-replace-content` performs find-and-replace over post content for explicit IDs or a taxonomy selection, with plain text or regex, case sensitivity control, and a `dry_run` match preview. Only `post_content` is modified. WordPress revisions remain the rollback path.
- `site-ai/detect-ai-slop` scores content with local deterministic heuristics: weighted AI-cliche phrase density, sentence-length uniformity, stock transition starters, em-dash and rule-of-three density, and lexical diversity. It is a review signal, not proof of AI authorship, and it never calls an external service.

All three accept `post_ids` or a `taxonomy` + `terms` selection with `post_type`, `post_status`, `order`, `limit`, and `offset`. Write operations enforce per-post `edit_post` checks; posts the authenticated user cannot edit are skipped and reported.

## Grok OAuth

Site AI Control 0.3.3 adds Grok's published CIMD client identity to the `wp-media/mcp-oauth` trusted-publisher list using the library's official `wpmedia_mcp_oauth_trusted_publishers` filter. Grok can therefore use the same OAuth MCP endpoint without weakening the trusted-publisher model. Grok client metadata: `https://grok.com/oauth/mcp-client.json`.


## Site AI Control 0.5.1

### OAuth compatibility fix

- Restores the `wpmedia_mcp_oauth_allow_untrusted_providers` compatibility filter so valid CIMD clients can reach the consent screen with older `Enable Abilities for MCP` / `wp-media/mcp-oauth` versions that reject untrusted clients by default.
- This does not mark every client as a verified publisher. The OAuth consent screen must display the client identity, and users should authorize only clients they trust. OAuth metadata, redirect URI, PKCE and token validation remain the responsibility of the maintained OAuth library.
- The Grok diagnostics row no longer claims that the publisher is trusted merely because the OAuth plugin is installed.

## Site AI Control 0.5.0

### Portability and MCP compatibility

- The plugin remains provider-neutral and registers abilities through the WordPress Abilities API for exposure by the installed MCP Adapter.
- The admin diagnostics page shows the WordPress, Yoast, Site Kit, MCP Adapter and OAuth integration status and the locally generated endpoints.
- OAuth compatibility permits valid unverified CIMD clients to reach consent when supported by the installed OAuth library. Review consent carefully; the Grok trusted-publisher entry only applies when the client ID exactly matches the published metadata URL.
- Application Passwords are intended for compatible local agents/bridges using dedicated least-privilege WordPress accounts, not for pasting into hosted chat tools.

### Yoast term metadata

Added two abilities:

- `site-ai/get-yoast-term-meta`: reads allowlisted Yoast metadata for a taxonomy term.
- `site-ai/update-yoast-term-meta`: updates only supplied allowlisted fields for a taxonomy term.

Supported term fields: SEO title, meta description, canonical URL, focus keyphrase, OpenGraph title/description and Twitter title/description. The ability rejects non-public or non-admin-visible taxonomies, checks WordPress term-management capability, validates canonical URLs and does not expose arbitrary term metadata.

The existing `site-ai/update-yoast-meta` ability now accepts supported public, UI-managed post types (including eligible custom post types), while excluding attachments and revisions. It enforces per-object edit permissions.

### Compatibility notes

MCP availability depends on the installed WordPress Abilities API, MCP Adapter, authentication layer and the client’s supported protocol/authentication flow. A common endpoint does not guarantee that every client supports the same OAuth flow. Test connections after installation or upgrades. Global Yoast archive templates and author archive settings are not changed by the term metadata abilities; they require a separate, version-aware global-settings module.
